## Modifications made in this fork

### Branding

- Application name changed from "RustDesk" to **"NetControl"**
  (`libs/hbb_common/src/config.rs`: `APP_NAME`). ASCII only, because the value
  is used in filesystem paths (config/log directories), the Windows service
  name and shortcuts.
- All application icons, tray icons, the in-app side-panel logo and the
  desktop launcher entry replaced with the operator's own logo
  (`brand/icon.svg` is the single source; `brand/gen_icons.sh` regenerates
  `res/*.png`, `res/*.ico`, `res/scalable.svg`, `res/logo*.svg`,
  `flutter/assets/icon.svg`, `flutter/assets/logo_dark.png`,
  `flutter/assets/logo_light.png`).
- Accent/button colour palette changed throughout the Flutter UI
  (`flutter/lib/common.dart`'s `MyTheme`, plus a handful of hardcoded
  gradient/border colours under `flutter/lib/desktop/`) from RustDesk's
  default blue to the operator's brand colour `#2A5FE0`.

### Package naming

- The Linux package, binary, installation paths, systemd unit and desktop
  entries were renamed from `rustdesk` to `netcontrol`
  (`flutter/linux/CMakeLists.txt`'s `BINARY_NAME`, `res/netcontrol.desktop`,
  `res/netcontrol-link.desktop`, `res/netcontrol.service`, packaging paths in
  `build.py` and `res/rpm-flutter.spec`). The Debian `postinst` additionally
  removes a previously installed `rustdesk` service when upgrading from an
  earlier build.
- The `rustdesk://` URI scheme is **deliberately kept** alongside the new
  `netcontrol://` scheme, because deep links are generated by a third-party
  admin panel that emits the former. Link parsing in the client does not look
  at the scheme name at all (`flutter/lib/common.dart` reads only the
  authority and path), so both work identically.
- Internal Cargo package and library names (`rustdesk`, `librustdesk.so`) were
  **not** renamed: the Flutter side loads the library by that name over FFI,
  and these names are not visible to end users.

### Self-hosted server

- Default rendezvous/relay server changed to a self-hosted server instead of
  RustDesk's public network (`libs/hbb_common/src/config.rs`:
  `RENDEZVOUS_SERVERS`, `RS_PUB_KEY`, `PROD_RENDEZVOUS_SERVER`). The real
  server address and public key are applied at build time via
  `brand/apply_local_server.sh` and are intentionally excluded from this
  repository (see `/local/` in `.gitignore`); the values committed here are
  placeholders.
- `hide-powered-by-me` is enabled by default in `BUILTIN_SETTINGS`, which
  removes the "Powered by RustDesk" widget.

### Removed third-party promotion

- The "new version available" card linking to `rustdesk.com/download` and to
  upstream releases (`flutter/lib/desktop/pages/desktop_home_page.dart`).
- The "you are using the public server" hint linking to
  `rustdesk.com/pricing` (`flutter/lib/desktop/pages/connection_page.dart`).
- The end-user licence link to `rustdesk.com/privacy.html` on the installation
  screen (`flutter/lib/desktop/pages/install_page.dart`).
- "Help" buttons pointing at `rustdesk.com` documentation in the Linux SELinux
  and Wayland warnings. The warnings themselves are kept — they are
  operational, not promotional.
- A "Source Code (AGPL-3.0)" link on the About screen points to this
  repository, to satisfy AGPL-3.0 §13 (network use) and §6 (conveying).

### Maintenance tooling

`brand/` contains the scripts that make this fork rebasable onto new upstream
releases: `vendor_hbb_common.sh` re-vendors `libs/hbb_common` at the submodule
revision an upstream tag points to and re-applies the branding constants,
`brand_hbb_common.py` performs those constant edits (failing loudly if
upstream renames one, rather than silently producing an unbranded build),
`gen_icons.sh` regenerates every icon from a single SVG, and
`apply_local_server.sh` injects the real server address and key before a build.

Upstream copyright notices and the AGPL-3.0 license text (`LICENCE`) were
**not** modified or removed. No changes were made to the core remote-desktop
protocol, encryption, or connection logic beyond the default server address
above.
